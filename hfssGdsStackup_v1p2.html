    HFSS GDS Stackup Generator
    
 
    Define how each GDS layer becomes a 3D body in HFSS, then export a PyAEDT script that imports the GDS file into
 the HFSS design that is currently open in AEDT.
    
 
    Workflow
    
 
      
  
    1. Set the GDS file and fill in the layer table. Save config / Load config store everything in a
   .json file; the last state is also remembered in this browser.
      2. 
  
    2. Export script and put it next to the GDS file (or enter an absolute GDS path).
      3. 
  
    3. In AEDT, open the project and the HFSS design to import into, then run the script with
   Automation > Run PyAEDT Script (CPython). Tools > Run Script (IronPython) is not supported;
   the script prints a message and stops there.
      4. 
 
    
 
    What the script does
    
 
      
  
    • Works in the active project and design. It does not change the solution type, model units, setups,
   existing objects, boundaries or variables, and it does not save anything.
      • 
  
    • Variables: every layer NAME uses NAME_lowerElevation and NAME_thickness
   (no thickness variable for zero-thickness layers). A variable that already exists in the design or project is
   reused unchanged, so its HFSS value wins over the table. A missing one is created as a design variable with the
   value from the table (plain numbers get the Units for table values). Helper variables are handled the same way. The script
      prints which variables were reused and which were created, and stops before importing if a variable it has to create
      uses a variable that exists neither in HFSS nor in the tables.
      • 
  
    • Import: one import_gds_3d() call per row, as flat sheets (import method 1). The new objects are
   swept by NAME_thickness and moved by NAME_lowerElevation, so changing a variable in HFSS
   moves or resizes the layer.
      • 
  
    • Zero thickness: the layer stays a sheet and gets a Perfect E boundary PerfE_GROUP instead of a material.
      • 
  
    • Materials must exist in the AEDT library; the script stops before importing if one is missing (no materials are created).
      • 
  
    • Names: each layer's objects go into one group named NAME, or NAME_2, NAME_3, ...
   if that name is already used. Objects are named GROUP_obj1, GROUP_obj2, ... (this pattern never
   blocks a future group name). All names are checked against existing objects, groups and boundaries, because AEDT uses
   one namespace for them. The script prints each group with its member count and a table with the z range of each object.
      • 
 
    
 
    Table and config
    
 
      
  
    • Settings: GDS file (absolute, or relative to the folder of the script) and the file name of the exported script.
   The GDS file's own units are used for the layout.
      • 
  
    • Units for table values (in the Layers header): units given to plain numbers in the Layers and Helper
   variables tables. Expressions keep the units you type.
      • 
  
    • Layers: name, Type, GDS layer number, z bottom, thickness and material. z top is computed for the preview.
   Row buttons: move up / down, ⊼ stack on the previous row (z bottom = PREV_lowerElevation + PREV_thickness),
   duplicate, delete. + Add layer adds a row on top of the last one; Sort by z orders rows by z bottom, then thickness.
      • 
  
    • Layer names must be valid HFSS variable names (letters, digits and _, not starting with a digit) and unique.
      • 
  
    • Type (layer / via) affects only this tool: vias are drawn as posts and are left out of the overlap check (a via
   inside a dielectric is normal; HFSS material precedence handles it). Type is saved in the config, not in the script.
      • 
  
    • Helper variables (optional) are extra HFSS variables for the layer expressions; use a $ prefix for project
   variables. A helper with the same name as a per-layer variable (e.g. SUB_thickness) takes precedence (shown as a warning).
      • 
  
    • No separate stackup file is needed: the layer table and helper variables are written into the exported script
   (STACKUP and VARIABLES at its top). Use Save config / Load config (.json) to store and
   reload a stackup; configs from older versions load too (removed settings are ignored). You can also drag & drop a
   .json config anywhere on the page.
      • 
  
    • Undo / Redo (Ctrl+Z, Ctrl+Y or Ctrl+Shift+Z) step through the last 100 changes to layers,
   helper variables, settings and units, including loading a config. A field edit counts as one change when you leave the
   field or press Enter. While the cursor is in a text field the shortcuts undo the typing in that field, as usual. The
   history is kept only while the page is open.
      • 
  
    • Expressions: + - * / ^ ** ( ), pi, abs sqrt min max sin cos tan exp ln, numbers with units
   (nm um mm cm meter mil in ...). Give numbers inside expressions explicit units (0.5um). Unknown variables
   are shown as warnings (they must already exist in HFSS), and the layer is left out of the drawing and the overlap check.
      • 
  
    • Validation: red = error (export asks for confirmation), yellow = warning; click a message to jump to the field. Rows
   that are still incomplete or invalid are left out of the script and listed in a comment in it. A GDS layer that
   contains no shapes is reported by the script (<-- CHECK) and skipped.
      • 
  
    • Cross-section: hover a layer for details, click it to jump to its row; Equal spacing draws all levels evenly (not to scale).
   Copy copies the script preview; Theme toggles light / dark; License shows the license and attribution.
      • 
 
    
 
    Tested with AEDT 2025.2 and PyAEDT (ansys-aedt-core) 0.18. Runs fully offline; no data leaves your browser.
